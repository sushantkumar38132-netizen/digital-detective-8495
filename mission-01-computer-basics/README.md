## 4. Understanding

### Task 1.1 — Trace one activity using IPOS
**Chosen Activity:** Typing and saving a text document in an editor.

| Stage | What happens in this example? | Hardware / component involved |
| :--- | :--- | :--- |
| **Input** | The user presses keys on the keyboard to enter text and clicks the button, speaks in the mic.   | Keyboard, Mouse,Camera or Microphone. |
| **Processing** | The CPU translates input into character codes (ASCII/Unicode), instructs the text editor process, and prepares data in RAM. | CPU (Processor) and Memory |
| **Output** | The graphics processor and screen display characters and interface visually in real time, convert electrical audio signal into audible sound waves. | Monitor, Speaker or printer |
| **Storage** | When "Save" is clicked, the file buffer is written from volatile RAM to non volatile storage as a file. | SSD (Solid State Drive) / Hard Disk |

#### How the activity flows from Input to Storage:
1. **Input to Processing:** The keyboard controller detects key pressed, converts them into codes, and interrupt the operating system.
2. **Processing to Output:** The CPU executes instructions within the application to insert characters into memory. The operating system instructs the display driver show on the monitor so the user gets instant visual feedback.
3. **Processing to Storage:** Upon initiating the save action (`Cmd+S` / `Ctrl+S`), the application requests the operating system's file system to transfer from temporary RAM into permanent non-volatile storage the SSD.
